## Codex runtime contract

This is the Codex port of pstack. Apply this contract to the workflow and every referenced file; it supersedes inherited orchestration details.

- Invoke sibling skills with `$name`, resolving their installed directory. Skill references are workflows, not shell commands.
- Use the actual tools exposed in this session. For parallel work use Codex collaboration tools (`spawn_agent`, messaging, and waits) when available, within the session's concurrency limit. Tool schemas are authoritative: role labels, background flags, and read-only labels below describe intent, not additional tool arguments. For read-only work explicitly prohibit edits in the delegated prompt. A role is an instruction, not a registered agent type.
- Default every delegate to the parent model. `inherit-parent` is a policy label: omit a model override. Never send it as a model identifier. Consult `~/.codex/pstack-models.md` if present; use only identifiers exposed by the current tool and compatible fork settings. Different reviewers using the same model are independent passes, not cross-provider validation. Report that limitation. If delegation is unavailable, execute passes sequentially and disclose the loss of independence.
- Respect concurrency and budget constraints even when a workflow describes a large fleet. Batch independent tasks. Give writers separate worktrees or disjoint paths as required by the project. Never reset, rebase, clean, or overwrite unrelated work. Reuse an existing agent where supported; repeat its current instructions when needed.
- For a poteto-style delegate, instruct it to read the installed `poteto-mode/SKILL.md`, this contract, and the selected playbook. For comment review use `$no-comments`. Do not assume named agent registrations exist.
- Use available planning tools or a short local checklist instead of assuming a todo tool exists. Use shell `rg`, file reads, and the session's search tools instead of assuming named search/read tools.
- `$create-skill` means the available `$skill-creator`. `$deslop` means inspect the scoped diff, remove needless additions and repair correctness issues, then validate; it does not require another plugin. `control-cli` means shell/PTY interaction; `control-ui` means an available browser or computer-use skill. If a required capability is unavailable, report the verification gap instead of claiming a pass. `/loop` is a bounded continuation workflow, not a supported command here.
- Use only available GitHub connectors or CLI capabilities. Do not assume `gh`, internal services, browser sessions, or credentials exist. Missing integrations are limitations, not evidence of absence. No skill invocation authorizes sending messages, merging, publishing, or widening the user's scope on its own.
- Session history access is host-dependent. Use supplied context first, then available history features or scoped local session records if accessible. Do not assume a transcript schema, path encoding, or permissions. Never copy private transcript content into this public-source adaptation repository.
- Installed output is generated. To modify these skills, follow `$update-pstack` and edit the adaptation repository, never installed output or the upstream snapshot by hand.

- Cloud-agent fleets, cloud-sleeper chains, Bugbot, internal Origin commands, and terminal loop/goal syntax in inherited playbooks are not bundled capabilities. Use bounded local Codex delegation and available wait tools; do not create a persistent goal unless the user explicitly requested one. For long-running work, report host limitations rather than simulating a cloud scheduler. Read playbooks from this installed skill's directory, never from an assumed path in the user's Git repository. Locate any referenced project script before running it; if absent, use available project checks or implement an authorized equivalent.
